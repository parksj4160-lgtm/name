# 크리스탈 디펜스 — 자동 개선 백로그

이 파일은 **5시간마다 자동으로 실행되는 개선 루틴**이 읽고 쓰는 작업 노트다.
각 실행은 새로운 세션에서 시작하므로, 이 파일이 유일한 연속성의 근거다.

## 규칙

1. **세션을 끝까지 쓴다.** 개선 하나로 끝내지 말고, 컨텍스트가 거의 찰 때까지(약 90%) 백로그를 계속 소화한다.
2. **하나를 완결하고 다음으로 간다.** 여러 개를 동시에 벌여놓지 않는다. 구현 → 검증 → 빌드 → 커밋 → 푸시를 한 항목마다 완주한다.
3. **항목마다 즉시 커밋·푸시한다.** 세션이 언제 끝날지 모르므로, 검증을 통과한 작업은 그 자리에서 원격에 남긴다. 마지막에 몰아서 커밋하지 않는다.
4. **검증 없이 넘어가지 않는다.** 헤드리스 브라우저로 실제 게임을 띄우고, 스크린샷을 눈으로 확인하고, 콘솔 에러가 0인지 본다.
5. **깨진 코드는 푸시하지 않는다.** 원인을 못 찾으면 되돌리고, 시도한 내용과 막힌 지점을 아래 `막힌 것들`에 기록한다.
6. **백로그가 비면 채운다.** 직접 플레이 테스트를 해서 새 항목을 발굴하고, 우선순위를 매겨 백로그에 추가한 뒤 계속 작업한다.
7. 기존 게임플레이를 깨뜨리지 않는 것이 항상 최우선이다. 장르 변경이나 핵심 규칙 교체 같은 큰 결정은 하지 않는다.

## 백로그 (우선순위 순)

- [ ] **사운드** — Web Audio API로 효과음 합성 (외부 파일 없이). 타격, 건설, 채집, 웨이브 시작, 크리스탈 피격. 음소거 토글 포함.
- [ ] **타격감** — 몬스터 피격 시 히트 플래시 · 넉백 · 화면 흔들림(보스 처치 시). 지금은 데미지가 들어가도 반응이 밋밋하다.
- [ ] **모바일 조작** — 조이스틱 반응성 개선, 건설 모드에서 탭-투-배치 UX 정리, 세로 화면 대응.
- [ ] **난이도 곡선** — 웨이브 3~6 구간이 헐겁고 8~10이 급격한지 실제 플레이로 점검하고 튜닝.
- [ ] **몬스터 다양성** — 원거리 공격형, 또는 타워를 우선 노리는 유형 추가. 벽 세우기 전략이 단조로워지는 걸 막는다.
- [ ] **타워 다양성** — 독/감전 등 지속 피해 타워, 또는 주변 타워를 강화하는 보조 건물.
- [ ] **통계 화면** — 최고 웨이브 · 총 처치 수 · 플레이 횟수를 localStorage에 기록하고 결과 화면에 표시.
- [ ] **튜토리얼** — 첫 플레이 시 채집 → 건설 → 웨이브 흐름을 3단계로 안내하는 오버레이.
- [ ] **웨이브 예고** — 다음 웨이브에 어떤 몬스터가 몇 마리 오는지 준비 시간에 미리 보여준다. 무엇을 지을지 판단할 근거가 생긴다.
- [ ] **건물 체력 표시** — 벽·타워가 얼마나 상했는지 한눈에 보이게. 어디를 수리/보강할지 판단이 가능해진다.
- [ ] **수리 기능** — 손상된 건물을 자원을 써서 수리. 지금은 부서지면 다시 짓는 수밖에 없다.
- [ ] **일시정지** — `P` 또는 `Esc` 로 게임 정지. 지금은 준비 시간에도 쉴 틈이 없다.
- [ ] **카메라 개선** — 확대/축소 범위 조정, 부드러운 추적, 건설 모드에서 시야 확보.
- [ ] **접근성** — 색약 모드(적/아군 구분을 색 외 형태로도), 키 리바인딩.
- [ ] **성능** — 몬스터·건물이 많아질 때 InstancedMesh 도입 검토. 후반 웨이브 프레임 여유 확보.
- [ ] **결과 화면 개선** — 웨이브별 생존 시간, 자원 사용 내역 등 되돌아볼 거리를 준다.
