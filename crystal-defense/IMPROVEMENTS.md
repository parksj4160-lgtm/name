# 크리스탈 디펜스 — 자동 개선 백로그

이 파일은 **5시간마다 자동으로 실행되는 개선 루틴**이 읽고 쓰는 작업 노트다.
각 실행은 새로운 세션에서 시작하므로, 이 파일이 유일한 연속성의 근거다.

## 규칙

1. **세션을 90% 가까이 적극적으로 쓴다.** 하나 하고 끝내지 말고 계속 다음으로 넘어간다.
   단 **새 항목 착수는 80% 전까지만** — 그 뒤로는 진행 중인 것을 마무리·검증·기록·푸시하는 데 쓴다.
2. **최우선순위는 ① 버그 수정 ② 재미·창의성·게임성.** 플레이하다 이상한 걸 발견하면 새 기능보다
   먼저 고친다. 그다음이 플레이어가 체감할 새로운 것(적·무기·상황·선택지)이다.
   UI 정리나 리팩터링은 위 둘을 방해하지 않는 선에서만.
3. **하나를 완결하고 다음으로 간다.** 구현 → 검증 → 빌드 → 커밋 → 푸시 → 아티팩트를 항목마다 완주한다.
   여러 개를 동시에 벌여놓지 않는다.
4. **항목마다 즉시 커밋·푸시한다.** 세션이 언제 끝날지 모른다. 마지막에 몰아서 하지 않는다.
5. **검증 없이 넘어가지 않는다.** 헤드리스로 실제 게임을 띄우고, 스크린샷을 눈으로 보고, 콘솔 에러 0 확인.
6. **깨진 코드는 푸시하지 않는다.** 원인을 못 찾으면 되돌리고 `막힌 것들`에 기록한다.
7. **이미 한 작업을 반복하지 않는다.** 백로그에 적기 전에 아래 완료 기록을 확인하고 `grep` 으로
   그 기능이 코드에 정말 없는지 검증한다.
8. **의미 없는 수정으로 세션을 낭비하지 않는다.** 개선이 아니라 변경을 위한 변경이면 하지 않는다.
9. **사용자에게 묻지 않고 승인을 기다리지 않는다.** 스스로 판단해서 진행한다.
10. 장르는 유지한다. 3D 웨이브 디펜스와 파밍 → 건설 → 방어의 순환은 그대로 두고 그 안에서 넓힌다.
11. 새 기능에는 **플레이어가 알아차릴 방법**(토스트·표시·도움말 한 줄)을 반드시 같이 넣는다.
12. 보고는 **무엇을 바꿨는지만** 짧게. 검증 과정·내부 용어는 빼고, 플레이어가 체감할 변화 중심으로.
13. **이 파일을 아티팩트의 CRYSTAL-DEFENSE-NOTES HTML 주석에 심기 전, 이 파일 안에
    "하이픈-하이픈-꺾쇠"(HTML 주석 종료 기호)가 코드·정규식 예시 등 어디에든 있는지 반드시
    `grep -n -- '--[>]'` 로 확인한다. 있으면 주석을 그 지점에서 조기 종료시켜 페이지 전체가 깨진다
    (실제로 한 번 발생했다 — 2026-08-23, 복구 절차 안 정규식 예시의 종료 패턴이 원인). 있으면
    게시 직전에만 HTML 엔티티(꺾쇠를 `&gt;`)로 바꿔서 주석에 넣는다(파일 자체는 그대로 둔다,
    코드 예시가 망가지면 안 되므로). 이 파일에 새로 코드·정규식 예시를 추가할 때도 그 3글자가
    연속으로 나오지 않게 쓴다(문자열을 쪼개거나, 코드 없이 문장으로만 설명한다).

## ⚠️ 0단계 — 저장소가 아티팩트보다 뒤처졌는지 먼저 확인하고, 그렇다면 복구부터

예약 세션은 `git push` 가 403 으로 거부될 때가 있다:

> access denied by the git proxy: parksj4160-lgtm/name is not in this session's
> authorized repository set

읽기는 되고 쓰기만 막힌다. 그렇게 끝난 회차의 작업은 **아티팩트에만** 남고 origin 은 뒤처진다.
**그 복구는 다음 실행이 자동으로 한다. 사람을 기다리지 않는다.**

1. 아티팩트를 `action: "read"` 로 읽어 맨 위 `CRYSTAL-DEFENSE-NOTES` 주석의 `STATUS:` 줄을 본다.
2. `STATUS` 가 "origin 이 최신" 이고 `git log` 도 그와 맞으면 → 복구 불필요, 바로 새 개선으로.
3. 아티팩트가 앞서 있으면(저장소에 없는 완료 기록이 주석에 있으면) → **복구를 먼저 끝내고 푸시한다.**
   절차는 아래 `막힌 것들` 에 상세히 적혀 있다.

**이번에도 푸시가 막히면:** 로컬 커밋은 정상적으로 쌓아 두고, 아티팩트 게시 시 주석에
이 파일 **전문**과 `STATUS:` 줄(무엇이 origin 에 못 갔는지)을 반드시 함께 심는다.
그게 다음 실행이 복구할 유일한 근거다. **작업을 버리지 않는다.**

**순서 규칙:** 소스를 먼저 커밋·푸시하고 그다음 아티팩트를 게시한다.

**사용자 요청: "재밌게 하고 새롭게 만들어줘", "계속 최고의 게임으로".**
다듬기만 하지 말고 **새로운 재미**를 넣는다. 아래는 전부 현재 코드에 없음을 grep 으로 확인했다.
위에서부터 하나씩 완결하고, 다 비면 직접 플레이해 새로 채운다.

(2026-08-23 세션이 처음 받은 8개 항목 + 직접 플레이로 채운 6개(덫탑·축복·비행균형측정·운석·
공성대형·삼위일체 업적)를 전부 소진하고 다시 채운 목록 — 이번 세션은 통합 검증까지 마쳤다)

(무기 강화는 예약 세션이 이미 완결해 아티팩트에서 복원 완료 — 완료 기록 참고. 백로그는 다시 비었다.)

### 환경 메모 (2026-08-22) — 헤드리스 검증 시 시간 흐름 주의

이 컨테이너는 GPU 가 없어 `requestAnimationFrame` 이 느리게(수 fps) 돈다. `main.js` 의 `dt` 는
`Math.min(0.05, (now-last)/1000)` 로 프레임당 최대 0.05초로 묶여 있어서, 실제 화면 프레임이 느리면
게임 내부 시간도 그만큼 느리게 간다 — **벽시계로 2초를 기다려도 게임 시간은 0.5초 정도만 지날 수 있다.**
채집(1.5~3초)·웨이브 준비 시간(60초+)처럼 시간이 걸리는 것을 `waitForTimeout` 으로 검증하면 실패처럼
보이는데, 실제로는 버그가 아니라 이 시간 배율 때문이다. 이번 세션에 이걸로 한참 헤맸다(나무를 캐도
목재가 안 늘어서 채집이 고장난 줄 알았는데, 그냥 게임 시간이 덜 지난 것이었다).
**다음 실행이 지킬 것:** 시간이 걸리는 로직을 검증할 땐 `page.evaluate` 로 상태를 직접 바꾸거나
`tickHarvest`/`wave.update` 같은 메서드를 직접 여러 번 호출해서 게임 시간을 강제로 흘리고,
`waitForTimeout` 은 이미 언급된 대로 짧은 UI 반응(토스트, 클래스 토글) 확인용으로만 써라.

### 성능 측정 (2026-08-22) — 로직 병목 없음

렌더를 빼고 `game.update()` 만 300회 호출해 CPU 비용을 쟀다 (타워 24개 · 웨이브 10 기준).
컨테이너에 GPU 가 없어 화면 FPS 자체는 의미가 없으므로, GPU 와 무관한 로직 비용만 본 것이다.

| 동시 몬스터 | 평균 | p95 | p99 |
|——-|——-|——-|——-|
| 20 | 0.50ms | 0.9ms | 1.5ms |
| 60 | 0.97ms | 2.1ms | 3.8ms |
| 100 | 1.64ms | 3.3ms | 4.4ms |

60fps 예산이 16.7ms 인데 성능 상한(`maxAlive` 120)에 가까운 100마리에서도 **10% 남짓**만 쓴다.
몬스터 수에 거의 선형으로 늘고 튀는 구간도 없다. InstancedMesh 도입 효과가 확인됐고,
로직 쪽에는 더 손댈 병목이 없다. 남은 비용은 렌더링 쪽이라 GPU 있는 환경에서 재야 한다.

### 멀티플레이 검증 (2026-08-22) — 정상 동작 확인

같은 브라우저에 탭 두 개를 띄워 BroadcastChannel 로 실제로 붙여 봤다. 전부 정상이었다.

| 항목 | 결과 |
|——-|——-|
| 방 만들기 · 코드로 참가 | 양쪽 로비 목록에 2명 표시 |
| 호스트 선출 | 먼저 들어온 쪽만 `isHost` |
| 맵 시드 | 양쪽 동일 |
| 참가자의 건설 요청 | 호스트가 처리 → 양쪽 건물 1개, 팀 자원도 25로 일치 |
| 웨이브 시작 | 양쪽 `combat` 으로 동기화 |
| 위치 동기화 | 정상 (아래 주의 참고) |

**주의 — 탭 두 개로 테스트할 때의 함정:** 백그라운드 탭은 브라우저가 `requestAnimationFrame` 을
강하게 제한한다. 실측에서 호스트 탭이 뒤에 있을 때 **2fps**, 앞에 있을 때 9fps 였다.
그래서 "참가자가 움직였는데 호스트 화면에서 안 따라온다" 처럼 보이는데, 이건 동기화 버그가 아니라
호스트 탭의 루프가 거의 멈춰 있어서다. `RemotePlayer.update()` 를 직접 호출해 보면 즉시 수렴한다.
실제 플레이에서는 각자 창이 앞에 있으므로 문제가 되지 않는다. **다음 실행이 같은 함정에 빠지지 않도록
`page.bringToFront()` 로 측정 대상 탭을 앞에 두고 재라.**

### 통합 검증 (2026-08-22, 이번 세션 후반) — 이번 세션에 추가한 기능 전부 한 판에서 같이 굴려봄

백로그를 다 소진한 뒤, 이번 세션에서 추가한 항목들(정수 스킬·엔드리스·변종 4종·타워 시너지·무기 4종·
업적·밤 웨이브·지형·서리 군주·함정·어려움·엔드리스 축복)을 개별 테스트만으로 남겨두지 않고
**한 판 안에서 전부 동시에** 돌려 상호작용 버그가 없는지 확인했다. 시너지 타워(서리+화살, 독+독)·함정·
무기(창)를 같이 짓고, 10웨이브를 순서대로 클리어하며 스킬 사용·양쪽 보스(파괴자/서리 군주) 처치·
업적 달성·엔드리스 전환까지 한 흐름으로 실행 — 콘솔 에러 0(파비콘 404 제외), 모든 수치가 예상대로.
실제 키보드·마우스 입력(프로그램적 상태 조작이 아니라 `page.keyboard`/`page.mouse`)으로도 이동·
인벤토리·건설·스킬 단축키·카메라 회전을 다시 확인해 실제 조작감도 문제없음을 확인.

이어서 **실제 브라우저 탭 두 개로 멀티플레이까지** 재검증(이번 세션 신규 기능 대상으로는 처음):
방 생성 → 참가 → 게임 시작 → 호스트가 지은 함정·제작대가 참가자 화면에 정확히 동기화 →
엔드리스 진입 후 축복(포격 강화)을 호스트가 고르면 참가자 화면에 안내 토스트가 뜨는 것까지 확인.
이 과정에서 크리스탈 `maxHp` 가 그동안 스냅샷에 안 실리고 있던 걸 발견해(체력 `hp` 만 동기화되고
있었음) `수정 결속` 축복을 만들면서 같이 고쳤다(`_snapshot`/`_applySnapshot`/`resumeLocal` 세 곳에
`cm` 필드 추가, 구버전 저장은 필드가 없어도 조용히 무시됨). 고친 뒤 같은 2탭 멀티플레이로 재검증해
호스트가 고른 수정 결속이 참가자 화면에도 정확히 반영되는 것 확인 — 양쪽 콘솔 에러 0.

### 2차 멀티플레이 검증 (2026-08-22, 세션 막바지) — 정예·보급품·결계·회피 돌진 4종 재확인

위 통합 검증 이후 추가한 4개 기능(⭐ 정예·📦 보급품 투하·🌀 결계 변종·💨 회피 돌진)은 개별 헤드리스
테스트는 각각 통과했지만 실제 2탭 멀티플레이에서는 아직 안 봤길래 한 번에 재확인했다. 정예의 체력·
색 배율, 결계의 태그·색, 보급품 픽업 후 자원 반영은 전부 호스트-참가자 화면이 정확히 일치. 회피
돌진의 무적 플래그도 `pos` 동기화로 정상 전파(직접 `net.send` 로 확인)됨을 확인.

이 과정에서 테스트 방법 자체의 함정 두 개를 만났다(둘 다 실제 버그 아님, 기록만 남김):
1. 결계 타워-회피 테스트에서 처음에 `enemyMgr.list` 를 안 비우고 확인했더니 타워가 "타깃을 찾음"으로
   나왔다 — 알고 보니 웨이브 1이 이미 자연 스폰한 다른(결계 아닌) 몬스터가 사거리 안에 있었던 것.
   리스트를 비우고 결계 개체만 남긴 채 재확인하니 정상(target=null). **여러 기능을 한 판에 같이
   테스트할 때는 자연 스폰된 몬스터가 섞여 들어올 수 있으니, 특정 개체 하나만의 동작을 확인하려면
   `enemyMgr.list.length = 0` 으로 반드시 비우고 시작할 것.**
2. 회피 돌진(지속시간 0.16초)의 네트워크 전파를 자연 게임 루프로 확인하려 했더니 계속 실패했다 —
   이 컨테이너는 GPU가 없어 rAF가 느리게 돌고(기존에 이미 문서화된 문제), `waitForTimeout` 동안
   실제 시간이 흘러 0.16초짜리 무적 창이 자연 루프 한 틱도 못 얻고 지나가버렸다. **기존에 문서화된
   "dt 조작 대신 실시간 우회" 교훈이 네트워크 전파 검증에도 그대로 적용된다** — `_netTick`의 주기적
   전송을 기다리는 대신 같은 페이로드로 `net.send("pos", {...})` 를 직접 호출해 전파 자체(net 배관)만
   따로 검증하니 바로 확인됨.

### 실기기 UI 점검 (2026-08-22, 세션 막바지) — 도움말·인벤토리가 콘텐츠 증가를 잘 버티는지

### 비행 몬스터 균형 측정 (2026-08-23) — 정상적인 타워 배치로 충분히 막힘

백로그의 "비행 몬스터 대응 확인" 항목을 헤드리스 시뮬레이션으로 검증했다. 방법: 화살탑 4개를
크리스탈 사방(십자 배치, 전형적인 "타워로 막기" 구도)에 짓고 실제 6웨이브 스탯의 🦇 박쥐 무리를
사방 20 거리에서 동시에 스폰시켜, 실제 게임 루프(`enemyMgr.simulate` + `buildMgr.updateTowers` +
`projectiles.update`)를 그대로 돌려 크리스탈 도달 여부와 피해를 쟀다.

| 시나리오 | 박쥐 수 | 타워에게 처치됨 | 크리스탈 도달 | 크리스탈 피해 |
|---|---|---|---|---|
| 화살탑 4개만 | 3(실제 6웨이브 수량) | 3/3 | 0 | 42 (4.2%) |
| 화살탑 4개 + 덫탑 1개 | 3 | 3/3 | 0 | 42 (동일) |
| 화살탑 4개만 | 6(과부하 가정) | 6/6 | 0 | 238 (23.8%) |
| 화살탑 4개 + 덫탑 1개 | 6 | 6/6 | 0 | 238 (동일) |

**결론: 사방을 커버하는 정상적인 타워 배치만으로 박쥐는 이미 100% 요격된다.** 덫탑 유무가 이
시나리오에서 전혀 차이를 안 만든 이유는 타워들이 이미 전부 잡아서 덫탑이 낄 틈이 없었기
때문이다. 즉 덫탑은 "박쥐를 막으려면 반드시 필요한 카운터"가 아니라, 타워 커버리지에 사각지대가
있거나(배치 초반, 자원 부족) 여러 마리가 한꺼번에 몰릴 때 시간을 벌어 주는 보조 수단으로
자리매김하는 게 정확하다. 도움말 문구("비행 몬스터에게도 통한다")는 사실과 맞고 과장은 아니지만,
"박쥐 카운터"로 오해하지 않도록 유의. 밸런스 수치는 건드릴 필요가 없다고 판단해 그대로 둔다
(타워 커버리지가 전혀 없는 극단적 사각지대 시나리오는 기하학적으로 어떤 적이든 뚫리는 게 당연해
박쥐만의 문제가 아니므로 별도 조치 대상이 아니라고 결론).

### 운석 낙하 빈도 측정 (2026-08-23) — 웨이브당 대략 0~1회, 적정 수준으로 판단

벽 링 + 타워 7개(화살탑 6·서리탑 1·대포탑 1) 방어선을 짓고 4~5웨이브를 실제 게임 루프
그대로(`wave.update`+`enemyMgr.simulate`+`buildMgr.updateTowers`+`projectiles.update`+
`_updateMeteor`) 돌려 운석이 언제 얼마나 뜨는지 쟀다. 4웨이브(전투 39.7초)에서 운석이 정확히
1회(t=24.5초, `firstDelay=22`+텔레그래프 부근) 떴고, 5웨이브(보스전, 전투 23.9초)에서는 뜨지
않았다 — 평균 주기가 약 55초(간격 40~65초+텔레그래프 2.5초)인데 웨이브 전투 시간이 그보다
짧으면 아예 안 뜰 수 있다는 뜻으로, 설계 의도("가끔")와 정확히 맞는다.

플레이어 개입 없는 자동전투라 방어선이 뚫려 5웨이브에서 크리스탈이 죽었는데(실전에서는 플레이어가
직접 싸우고 건물을 보수하므로 더 오래 버틴다), 운석 빈도 자체는 순수 타이머 문제라 전투 결과와
무관하게 유효한 값이다. **결론: 수치를 건드릴 필요 없음** — 매 웨이브 뜨는 게 아니라 어떤 웨이브는
아예 안 뜨고 어떤 웨이브는 한 번 뜨는 정도라 "성가심"보다는 "가끔 오는 변수"에 가깝다.

### 실제 2탭 멀티플레이 검증 (2026-08-23, 세션 막바지) — 이번 세션 신규 기능 대상 첫 실측

이번 세션 내내 시뮬레이션(단일 페이지에서 호스트/원격 로직을 흉내)으로만 검증하던 것을, 실제
브라우저 탭 두 개로 재검증했다. 처음엔 `browser.newPage()`를 두 번 불러 탭을 만들었더니 방
목록이 서로 안 보였는데 — Playwright 는 `newPage()`를 호출할 때마다 별도(시크릿모드류)
브라우저 컨텍스트를 만들어 BroadcastChannel(멀티플레이 기본 전송)이 격리된다는 걸 알아냈다.
`browser.newContext()`로 컨텍스트 하나를 만들고 그 안에서 `context.newPage()`를 두 번 불러야
실제 같은 창의 탭 두 개처럼 연결된다 — **다음 실행이 2탭 테스트를 짤 때 반드시 지킬 것.**

고친 뒤 방 생성 → 참가까지는 정상 확인, 이어서 이번 세션 신규 기능들을 실측:
- 호스트가 크리스탈 강화(강화 Lv.1, 정수 20 지불)를 사면 참가자 화면의 크리스탈 HP 바가
  1150/1150 으로 즉시 똑같이 바뀌는 것을 스크린샷으로 확인(둘 다 완전히 동일한 렌더링).
- 호스트가 만든 칼을 참가자에게 건네주면 호스트는 잃고 참가자가 정확히 받는 것을 확인.
- 호스트가 침묵의 군주를 스폰하면 참가자 화면에도 즉시 나타나는 것을 확인.
- 침묵 장판 재구성(캐스팅 플래그 1→0 전이 감지)은 자연 스냅샷 주기(1/12초)가 캐스팅 지속시간
  (1.1초)보다 느려서 실제 웨이브 진행 중엔 안 놓치지만, 이번처럼 한 프레임에 캐스팅→해제를
  몰아서 강제하면 중간 상태가 스냅샷에 안 실릴 수 있다(기존 회피 돌진 0.16초 무적 창과 같은
  부류의 타이밍 함정). 이번엔 그 함정에도 불구하고 호스트의 자연 주기 전송이 진짜 1→0 전이를
  만들어내 참가자가 `silenceUntil`을 정확히 재구성하는 것까지 실측으로 확인됐다(전 과정 진짜
  네트워크 페이로드로 오간 것 — 합성 호출이 아님). 콘솔 에러 0(파비콘 404 제외).

## 막힌 것들 · 아티팩트 → 소스 복구 절차 (검증된 스크립트)

예약 세션의 푸시가 403 으로 막혀 작업이 아티팩트에만 남는 일이 여러 번 있었다.
아래는 대화형 세션이 **네 번 실제로 써서 성공한** 복구 스크립트다. 그대로 따라 하면 된다.

**1) 아티팩트를 읽어 로컬 파일로 받는다.** `Artifact` 툴 `action: "read"` 로 URL 을 읽으면
전체 HTML 이 로컬 파일로 저장되고 결과에 그 경로가 나온다. 그 경로를 아래 `F` 에 넣는다.

**2) 번들을 잘라 모듈별로 되돌린다.**

```python
import re, os
F   = "<위에서 받은 아티팩트 HTML 경로>"
OUT = "<작업 디렉터리>/js"      # 미리 만들어 둘 것
lines = open(F, encoding='utf-8').read().split('\n')
orig = '\n'.join(lines[1:])                      # 1행은 호스트가 붙인 frame-runtime — 버린다
if orig.endswith('\n</body></html>'): orig = orig[:-len('\n</body></html>')]
open('artifact.html','w',encoding='utf-8').write(orig)

starts = [i for i,l in enumerate(lines) if l.strip() == '(() => {']
ends   = [i for i,l in enumerate(lines) if l.strip() == '})();']
s0 = starts[0]; e0 = max(e for e in ends if e > s0)   # 마지막 })(); 가 번들의 끝
bundle = '\n'.join(lines[s0+1:e0])

marks = [(m.start(), m.group(1)) for m in
         re.finditer(r'^  // ((?:js|vendor)/[\w.]+\.js)$', bundle, re.M)]
mods = {}
for i,(pos,name) in enumerate(marks):
    end = marks[i+1][0] if i+1 < len(marks) else len(bundle)
    mods[os.path.basename(name)] = bundle[pos:end]

# three.js 미니파이 심볼 → 실제 export 이름
three = open('vendor/three.module.js', encoding='utf-8').read()
pairs = re.search(r'export\{(.*?)\};?\s*$', three, re.S).group(1)
tmap = {}
for pr in pairs.split(','):
    mm = re.match(r'^([\w$]+) as ([\w$]+)$', pr.strip())
    if mm: tmap[mm.group(1)] = mm.group(2)

game = {k:v for k,v in mods.items() if k != 'three.module.js'}
decl = re.compile(r'^  (?:var|let|const|function|class)\s+([\w$]+)', re.M)
owner = {}
for f,b in game.items():
    if f == 'main.js': continue
    for d in decl.findall(b): owner.setdefault(d, f)

CTOR = re.compile(r'\bnew ([A-Za-z_$][\w$]*)\(')
cleaned = {}
for f,b in game.items():
    b = re.sub(r'^  // (?:js|vendor)/[\w.]+\.js\n', '', b)
    b = '\n'.join(l[2:] if l.startswith('  ') else l for l in b.split('\n')).rstrip() + '\n'
    b = CTOR.sub(lambda m: f"new THREE.{tmap[m.group(1)]}("
                 if m.group(1) in tmap and m.group(1) not in owner else m.group(0), b)
    b = b.replace('side: p', 'side: THREE.DoubleSide')
    b = b.replace('shadowMap.type = c;', 'shadowMap.type = THREE.PCFSoftShadowMap;')
    b = b.replace('toneMapping = nt;', 'toneMapping = THREE.ACESFilmicToneMapping;')
    b = re.sub(r'\\u\{([0-9a-fA-F]+)\}', lambda m: chr(int(m.group(1),16)), b)   # 한글 복원
    b = re.sub(r'\\u([0-9a-fA-F]{4})',     lambda m: chr(int(m.group(1),16)), b)
    cleaned[f] = b

# 모듈 간 import/export 재구성
ident = re.compile(r'(?<![\w$.])([A-Za-z_$][\w$]*)')
d2    = re.compile(r'^(?:var|let|const|function|class)\s+([\w$]+)', re.M)
decls = {f:set(d2.findall(b)) for f,b in cleaned.items()}
needed, imports = {}, {}
for f,b in cleaned.items():
    cross = {}
    for x in sorted(set(ident.findall(b)) - decls[f]):
        o = owner.get(x)
        if o and o != f: cross.setdefault(o, []).append(x)
    imports[f] = cross
    for o,syms in cross.items(): needed.setdefault(o, set()).update(syms)
for f,b in cleaned.items():
    hdr = []
    if 'THREE.' in b: hdr.append("import * as THREE from '../vendor/three.module.js';")
    for o in sorted(imports[f]):
        hdr.append(f"import {{ {', '.join(sorted(imports[f][o]))} }} from './{o}';")
    for sym in sorted(needed.get(f, ())):
        b = re.sub(rf'^((?:var|let|const|function|class)\s+{re.escape(sym)}\b)',
                   r'export \1', b, count=1, flags=re.M)
    open(f"{OUT}/{f}", 'w', encoding='utf-8').write(('\n'.join(hdr) + '\n\n' if hdr else '') + b)
```

**3) HTML · CSS · 이 파일을 되돌린다.** (`artifact.html` 기준)

```python
html = open('artifact.html', encoding='utf-8').read()
m = re.search(r'<!-- CRYSTAL-DEFENSE-NOTES[^\n]*\n(.*?)\n--' + r'>\n', html, re.S)
notes = re.sub(r'^STATUS:[^\n]*\n+', '', m.group(1))   # STATUS 머리말은 파일 본문이 아니다
open('IMPROVEMENTS.md','w',encoding='utf-8').write(notes.strip() + '\n')
html = html[:m.start()] + html[m.end():]
m = re.search(r'<style>\n(.*?)\n</style>', html, re.S)
open('css/style.css','w',encoding='utf-8').write(m.group(1).rstrip() + '\n')
html = html[:m.start()] + '<link rel="stylesheet" href="css/style.css" />' + html[m.end():]
m = re.search(r'<script>\n\(\(\) => \{\n.*?\n\}\)\(\);\n.*?</script>', html, re.S)
html = html[:m.start()] + '<script type="module" src="js/main.js"></script>' + html[m.end():]
html = re.sub(r'<title>.*?</title>', '<title>크리스탈 디펜스 (Crystal Defense)</title>', html, count=1)
```

**⚠️ 골격 복원을 잊지 말 것.** 아티팩트 호스트가 `<!DOCTYPE>`·`<html>`·`<head>`·`<body>` 를
벗겨내므로 `index.html` 은 `<title>` 부터 시작한다. 다시 씌워야 한다:

```python
k = html.index('<link rel="stylesheet" href="css/style.css" />') + len('<link rel="stylesheet" href="css/style.css" />')
head, body = html[:k], html[k:]
html = ('<!DOCTYPE html>\n<html lang="ko">\n<head>\n<meta charset="utf-8" />\n'
        '<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, '
        'user-scalable=no, viewport-fit=cover" />\n'
        + head.strip() + '\n</head>\n<body>' + body.rstrip() + '\n</body>\n</html>\n')
open('index.html','w',encoding='utf-8').write(html)
```
